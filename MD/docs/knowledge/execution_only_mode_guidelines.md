# Execution only mode guidelines

## מה זה EXECUTION_ONLY
- מצב שבו הפלט הוא הוראות טכניות למודל המתכנת בלבד
- הפלט חייב להיות דטרמיניסטי ומבני
- אין שיח מול לקוח ואין ניסוחי החלטה

## פורמט קשיח
- בדיוק ארבע כותרות
- הכותרות מסודרות לפי סדר קבוע
- אין טקסט לפני הכותרת הראשונה
- אין כותרות נוספות

## מה חייב להופיע בתוך SUCCESS
- תוכן טכני אמיתי, לא כללי
- פקודת בדיקות: python -m pytest -q
- פקודות Git: git add, git commit, git push
- פקודת curl.exe במסגרת PowerShell
- לפחות נתיב קובץ אחד מתוך הקוד כגון app/ או tests/ או Dockerfile

## מה אסור לעשות
- לא להציג סימן שאלה
- לא להשתמש בביטויי בקשת החלטה כגון האם או בחר
- לא להמציא מספרים או תוצאות מערכת

## אם אין מספיק מידע לביצוע
- לכתוב צעדים להשגת המידע מתוך המערכת או מהקבצים
- לכתוב סדר עבודה טכני להשגת המידע
- לא לשאול שאלות
- לא לייצר פעולה שמשנה מצב בלי צעד שמגדיר מקור מידע

## כללי כתיבה
- לכתוב פקודות כמו שהן, בלי קיצורים לא ברורים
- להקפיד על נתיבים יחסיים מתוך הפרויקט
- להקפיד על סדר עבודה ברור
- לא להוסיף שפה שיווקית או טקסט לקוח

## מה עושים במקרה כשל
- אם בדיקות נכשלות, לכתוב שלב איתור שגיאה ממוקד
- אם יש קובץ חסר, לכתוב מה ליצור ואיפה
- אם נדרשת קריאת קוד, לציין באיזה קבצים להתמקד
- להימנע מהסקת מסקנות בלי לקרוא את הפלט
